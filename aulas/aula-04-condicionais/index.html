Aula 4 — Condicionais (if / elif / else)

Objetivos

  • Usar if, elif e else.
  • Usar os operadores de comparação: ==, !=, >, <, >=, <=.
  • Usar os operadores lógicos and, or e not.
  • Testar se um item está numa lista com in.

Pílula da aula — "No fundo, tudo é 0 ou 1"

Dentro do computador não existe "mais ou menos": só bilhões de chavinhas ligadas ou desligadas. Em 1854, George Boole escreveu as regras para combinar verdadeiro e falso — muito antes de existir computador. É dessas regras que saem o and, o or e o not que vamos usar hoje.

Curiosidade: a palavra "bit" vem de binary digit, ou seja, dígito binário — uma única chavinha, que só pode estar em 0 ou em 1.

O que vamos ver

  • O tipo bool: só existem True e False, sempre com a primeira letra maiúscula.
  • A diferença entre = (guarda um valor) e == (faz uma pergunta).
  • A anatomia do if: palavra-chave, condição, dois pontos, e o bloco indentado com 4 espaços.
  • if / else.
  • if / elif / else — e por que a ordem das condições importa.
  • Os operadores lógicos and, or e not.
  • O operador in.
  • if dentro de for.
  • Normalizar a entrada do usuário com .strip().lower().

Ficou travado?

Seis erros que pegam quase todo mundo nesta aula:

  1. Esqueci os dois pontos. O Python avisa com SyntaxError. Todo if, elif e else termina com :.
  2. Usei = no lugar de ==. Também dá SyntaxError. Um sinal guarda um valor, dois sinais fazem uma pergunta.
  3. Recuo errado. Dá IndentationError. O bloco de dentro do if usa 4 espaços a mais que a linha do if.
  4. Comparei texto com número. "3" == 3 é False, porque um é texto e o outro é número. Converta antes com int().
  5. Escrevi true minúsculo. Dá NameError. Em Python é True e False, sempre com maiúscula.
  6. Nenhum erro, mas o resultado está errado. Aí é bug de lógica, não de sintaxe. Revise a ordem dos elif: o primeiro que der certo é o único que roda.

Exercício 1 — Alerta de vida baixa

ESSENCIAL · if simples · arquivo sugerido: exercicio_01_alerta_de_vida.py

Inspirado nos corações de The Legend of Zelda. Crie a variável vidas_restantes com o valor 2. Se ela for menor que 3, imprima um alerta. Depois do if, imprima sempre quantas vidas restam.

Rode duas vezes: uma com 2 vidas e outra com 5. Na segunda, o alerta não pode aparecer.

Exemplo de execução:

Cuidado! Vida baixa.
Você tem 2 vidas restantes.
Ver dica

Aqui não precisa de else. Um if sozinho resolve: quando a condição é falsa, o Python simplesmente pula o bloco e segue para a linha de baixo.

1. A porta do calabouço FÁCIL

if / else · arquivo sugerido: exercicio_04_porta_do_calabouco.py

Com a variável tem_chave valendo True ou False: se tiver a chave, a porta se abre; senão, avise que está trancada e diga o que a pessoa precisa procurar.

Ver dica

Escreva if tem_chave: sem o == True — a variável já é booleana, então ela já é a própria pergunta.

2. Atravessar a caverna FÁCIL

or e not · arquivo sugerido: exercicio_05_atravessar_a_caverna.py

Inspirado em Hollow Knight. Com as variáveis tem_mapa e tem_lanterna, use or: basta um dos dois para atravessar. Depois, acrescente um segundo if com not, que dê um aviso extra quando faltar lanterna — mesmo que a pessoa consiga passar pelo mapa.

Ver dica

Dois if separados podem rodar os dois na mesma execução. Isso é normal aqui: um decide se dá para passar, o outro só comenta sobre a lanterna.

3. Classificação indicativa da loja FÁCIL

input + int() + elif · arquivo sugerido: exercicio_06_classificacao_indicativa.py

Pergunte o nome e a idade da pessoa, converta a idade com int() e use if / elif / else para dizer o que ela pode jogar: 18 ou mais libera tudo; 16 ou mais, até 16; 12 ou mais, até 12; abaixo disso, só os jogos livres. Chame a pessoa pelo nome na resposta.

Ver dica

Sem o int(), a idade seria o texto "16", e comparar texto com número dá erro.

4. Isso está no inventário? FÁCIL

listas + in · arquivo sugerido: exercicio_07_isso_esta_no_inventario.py

Com uma lista inventario de pelo menos quatro itens, pergunte qual item a pessoa procura e responda usando in. Se ela não tiver o item, imprima a lista completa do que ela tem.

Ver dica

Use .strip().lower() na resposta, senão "Espada" não bate com "espada".

5. Tabela de tipos FÁCIL

comparação de texto + elif · arquivo sugerido: exercicio_08_tabela_de_tipos.py

Inspirado na vantagem de tipos de Pokémon. Com tipo_do_ataque valendo "agua" e tipo_do_inimigo valendo "fogo", cubra os casos: água contra fogo é super efetivo; fogo contra água é pouco efetivo; tipos iguais não têm vantagem; qualquer outra combinação causa dano normal.

Ver dica

Para o caso dos tipos iguais, compare as duas variáveis entre si: tipo_do_ataque == tipo_do_inimigo.

6. Contador de moedas MÉDIO

for + soma + if · arquivo sugerido: exercicio_09_contador_de_moedas.py

As 100 moedas que dão vida extra em Super Mario. Com a lista moedas_por_fase, some tudo usando for. Depois do laço, use if / elif / else: 100 ou mais ganha vida extra; 50 ou mais recebe um incentivo; abaixo de 50, "continue tentando".

Ver dica

A variável do total precisa existir antes do for, começando em zero — senão o Python não tem onde somar.

7. Quantos inimigos ainda estão de pé MÉDIO

if dentro de for · arquivo sugerido: exercicio_10_inimigos_de_pe.py

Percorra a lista vidas_dos_inimigos e conte quantos têm vida maior que zero. Depois do laço, imprima quantos restam — ou "Fase limpa!" se não restar nenhum.

Ver dica

8. A vitrine da loja MÉDIO

listas paralelas + for + if · arquivo sugerido: exercicio_11_vitrine_da_loja.py

Inspirado no mercador de Resident Evil 4. Com as listas itens_da_loja e precos, do mesmo tamanho, pergunte quantas moedas o jogador tem, percorra por índice e diga, item a item, se dá para comprar. No fim, conte quantos cabem no orçamento.

Ver dica

Use precos[indice] para pegar o preço do item que está na mesma posição da outra lista.

9. Barra de vida em texto (e em voz) MÉDIO

for + range + if · arquivo sugerido: exercicio_12_barra_de_vida.py

Com vidas (de 0 a 5) e vidas_maximas valendo 5, monte uma barra com [#] para vida cheia e [ ] para vida perdida. Imprima a barra e, na linha seguinte, a mesma informação por extenso ("Vida: 3 de 5") — essa segunda linha é a que funciona ouvida em voz alta. Use if para avisar "MODO CRÍTICO" com 1 vida e "Game Over" com 0.

Ver dica

10. Modo acessível: liga e desliga MÉDIO

booleano + if / else · arquivo sugerido: exercicio_13_modo_acessivel.py

O tema do curso em versão de bolso. Com modo_acessivel começando em True, mais pontos_ganhos e total_de_pontos: ligado, imprima uma frase completa e clara, feita para ser ouvida; desligado, a versão curta e visual, tipo "+40 (760)".

Rode nos dois modos e compare: as duas versões dão a mesma informação?

Exemplo de execução:

Alienígena destruído. Você ganhou 40 pontos. Total: 760 pontos.
Ver dica

Regra de ouro: no modo acessível, a frase precisa fazer sentido sozinha, sem depender de nada desenhado na tela.

Desafio da semana — Guia de Build

O que você vai construir

Um programa que faz três perguntas sobre o estilo de jogo da pessoa — prefere ataque ou defesa? luta de perto ou de longe? gosta de magia? — e recomenda uma classe a partir das respostas: guerreiro, mago, arqueiro, ladino, ou a que você inventar.

Por que isso é interessante

É uma versão simplificada de um "sistema especialista": a mesma ideia por trás de assistentes que recomendam coisas a partir de várias condições combinadas.

Requisitos mínimos

  1. Fazer pelo menos três perguntas com input().
  2. Usar if / elif / else.
  3. Usar pelo menos um and ou or.
  4. Toda pergunta precisa de um else para a resposta que você não previu.
  5. A recomendação final vem em frase completa, que faça sentido ouvida em voz alta.

Exemplo de execução

Um exemplo de como a conversa com o programa pode ficar:

Você prefere atacar ou se defender? (ataque/defesa): ataque
Você luta melhor de perto ou de longe? (perto/longe): longe
Você gosta de magia? (sim/nao): sim

Analisando seu estilo de jogo...

Pelo seu perfil, a classe ideal para você é: mago.
Você prefere atacar de longe e gosta de magia, então lançar
feitiços à distância combina mais com o seu jeito de jogar.

Vá além (opcional)

  • Sortear entre duas ou três classes válidas com random.choice().
  • Acrescentar uma quarta pergunta que funcione como desempate.
  • Guardar as respostas numa lista e imprimir um resumo do perfil no final.
  • Criar uma classe secreta que só aparece numa combinação rara.
  • Permitir informar o nome do personagem e incluí-lo na recomendação.

Como entregar

Arquivo desafio_04_guia_de_build.py, publicado no repositório do curso pela interface web do GitHub (Add file → Upload files).

Checklist de conclusão

  • Roda do começo ao fim sem erro.
  • Tem pelo menos três caminhos diferentes de resposta.
  • Nenhuma resposta do usuário quebra o programa.
  • A recomendação final é uma frase completa e compreensível lida em voz alta.
  • Está publicado no GitHub.

Nota de acessibilidade

Todo texto que o seu programa imprime pode ser lido por um leitor de tela. Prefira frases completas a códigos enigmáticos: "Você perdeu uma vida. Restam 2." funciona muito melhor no áudio do que "-1 HP".

Sobre a indentação: no Thonny, o leitor de tela anuncia a coluna do cursor. Dá para conferir o recuo sem enxergar a tela — o bloco de dentro de um if começa na coluna 5.
