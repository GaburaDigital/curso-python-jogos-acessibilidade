Aula 7 — Funções

Objetivos

  • Definir funções com def.
  • Passar informações por parâmetros.
  • Devolver resultados com return.
  • Usar valores padrão.
  • Importar módulos.

Pílula da aula — o que é um ambiente virtual

Imagine que cada projeto seu é uma oficina diferente, com suas próprias ferramentas na bancada. Um ambiente virtual é isso: uma caixa de ferramentas isolada por projeto, para que instalar algo em um trabalho não quebre outro.

Vocês vão usar isso de verdade na Aula 9, quando instalarmos o pygame-ce pelo Thonny.

O que vamos ver

  • O que é uma função e por que ela existe: escrever uma vez, usar quantas vezes quiser.
  • A anatomia do def: nome, parênteses, parâmetros, dois pontos e o bloco indentado.
  • A diferença entre parâmetro (o nome que aparece na definição) e argumento (o valor que você passa na hora de chamar).
  • A diferença entre uma função que imprime e uma que devolve com return — e por que a segunda é mais reaproveitável.
  • Valores padrão, para deixar um argumento opcional.
  • Argumentos nomeados.
  • Docstring: o comentário entre três aspas que explica o que a função faz.
  • Importar módulos da biblioteca padrão.
  • Guardar as próprias funções em um módulo separado.

Ficou travado?

Seis erros que pegam quase todo mundo nesta aula:

  1. Defini a função mas nada acontece. Definir não é chamar. Depois do def, falta uma linha chamando a função pelo nome, com parênteses.
  2. NameError: name 'x' is not defined ao usar fora da função. A variável criada dentro da função só existe lá dentro. Para usar fora, devolva com return e guarde numa variável.
  3. A função devolve None. Faltou o return. Sem ele, toda função devolve None automaticamente.
  4. TypeError: ... missing 1 required positional argument. Você chamou a função com menos argumentos do que ela pede.
  5. Os valores saíram trocados. Argumentos posicionais entram na ordem em que foram definidos. Use argumentos nomeados (sortear(minimo=1, maximo=10)) quando quiser garantir a ordem.
  6. IndentationError. O corpo da função precisa de 4 espaços, igual ao if e ao while.

Atenção: módulo próprio só funciona no Thonny

Esta aula termina ensinando a guardar suas funções em um arquivo separado — um módulo — e trazer de volta com import. Isso é central no curso: a partir da Aula 14, o jogo Invasão Alienígena é dividido em vários arquivos.

O que funciona aqui no site: importar módulos que já vêm com o Python, como import random, import math ou from random import randint. Esses exercícios têm editor normal e rodam direto na página.

O que não funciona aqui no site: criar o seu próprio arquivo de funções e importá-lo. O editor da página roda um trecho de código por vez e não dá para você criar um segundo arquivo .py ao lado dele. Não existe jeito de contornar isso, e também não vale a pena tentar: o lugar de fazer esse exercício é o Thonny, no seu computador, que é onde você vai programar de verdade da Aula 9 em diante.

Por isso, o último exercício de prática e o desafio da semana não têm editor aqui. No lugar dele, você encontra o código dos dois arquivos lado a lado, com o nome de cada um em cima, para você copiar no Thonny e salvar na mesma pasta.

1. Conversor de temperatura reaproveitado FÁCIL

return · arquivo sugerido: exercicio_04_conversor_reaproveitado.py

Transforme em função a lógica do conversor Celsius para Fahrenheit da Aula 2. A função recebe o valor em Celsius e devolve o valor em Fahrenheit. Chame com três temperaturas diferentes.

Ver dica

A função só faz a conta e devolve. Quem imprime é o código de fora — assim a mesma função serve para qualquer temperatura, em qualquer programa.

2. Rolador de dados FÁCIL

função + random · arquivo sugerido: exercicio_05_rolador_de_dados.py

Crie a função rolar_dado(lados=6), que sorteia um número de 1 até lados e devolve. Chame sem argumento (dado comum de 6 lados) e com lados=20 (dado de RPG).

Ver dica

O import random fica na primeira linha do arquivo, fora da função — você importa uma vez e todas as funções do arquivo podem usar.

3. Ficha formatada FÁCIL

função que monta texto · arquivo sugerido: exercicio_06_ficha_formatada.py

Ver dica

Use \n dentro do texto para quebrar linha, ou monte a string somando pedaços, como no código inicial.

4. Está vivo? FÁCIL

função que devolve True/False · arquivo sugerido: exercicio_07_esta_vivo.py

Crie a função esta_vivo(vida), que devolve True se a vida for maior que zero e False caso contrário. Use o retorno dentro de um if para decidir a mensagem.

Ver dica

Uma função pode devolver um booleano direto: return vida > 0 já é a resposta inteira, sem precisar de if dentro da função.

5. Caixa de ferramentas MÉDIO

várias funções no mesmo arquivo · arquivo sugerido: exercicio_08_caixa_de_ferramentas.py

Escreva três funções pequenas no mesmo arquivo: calcular_media(notas), maior_valor(numeros) e contar_itens(lista). Cada uma recebe uma lista e devolve um resultado. Chame as três com a mesma lista e imprima os resultados.

Ver dica

Separe as funções com duas linhas em branco — é a convenção da PEP 8, e ajuda muito a enxergar onde uma termina e a outra começa.

6. Função dentro do laço MÉDIO

Ver dica

7. Narrador do jogo MÉDIO

Duas funções: calcular_pontos(inimigos_derrotados), que só faz a conta e devolve, e narrar(mensagem), que imprime a mensagem em frase completa. Use as duas juntas. Repare que, se um dia você quiser mudar como o jogo fala, muda só a narrar().

Ver dica

8. Validando com função MÉDIO

Crie a função pedir_numero(mensagem), que pergunta ao usuário, repete enquanto a resposta não for um número válido, e devolve o número convertido. Use a função duas vezes no programa principal.

Cada pergunta abre uma caixa de diálogo, então este fica mais confortável no Thonny.

Ver dica

Use .isdigit() para checar se o texto digitado é formado só por dígitos — ainda não vimos try/except. A condição de parada do laço já vem escrita no código inicial: cuidado para não apagar.

9. Argumentos nomeados MÉDIO

ordem dos argumentos · arquivo sugerido: exercicio_12_argumentos_nomeados.py

Crie a função criar_item(nome, preco, raro=False). Chame três vezes: uma com os argumentos na ordem, uma usando argumentos nomeados fora de ordem, e uma marcando raro=True. Imprima o item devolvido em cada caso, uma informação por linha.

10. Minha primeira biblioteca AVANÇADO

módulo próprio · arquivos sugeridos: ferramentas_do_jogo.py e jogo_principal.py

Este exercício é feito no Thonny, não aqui no site. Ele precisa de dois arquivos salvos na mesma pasta, e o editor desta página roda um trecho de código por vez, sem lugar para criar um segundo arquivo. Copie os dois blocos abaixo no Thonny, salve com os nomes indicados, na mesma pasta, e rode o jogo_principal.py.

Você vai montar sua primeira biblioteca: um arquivo só com funções úteis, e outro que importa e usa essas funções. É assim que o jogo Invasão Alienígena vai ser organizado a partir da Aula 14.

Primeiro arquivo, só com as ferramentas:

ferramentas_do_jogo.py

"""Ferramentas reaproveitáveis para os jogos do curso."""

import random


def rolar_dado(lados=6):
    """Devolve um número sorteado de 1 até a quantidade de lados."""
    return random.randint(1, lados)


def esta_vivo(vida):
    """Devolve True se o personagem ainda tem vida."""
    return vida > 0


def montar_ficha(nome, classe, vida):
    """Devolve a ficha do personagem, uma informação por linha."""
    ficha = "Nome: " + nome + "\n"
    ficha = ficha + "Classe: " + classe + "\n"
    ficha = ficha + "Vida: " + str(vida)
    return ficha

Segundo arquivo, que usa as ferramentas:

jogo_principal.py

import ferramentas_do_jogo
from ferramentas_do_jogo import rolar_dado

# Forma 1: com o nome do módulo na frente.
dano = ferramentas_do_jogo.rolar_dado(20)
print("Dano do golpe: " + str(dano))

# Forma 2: importando a função direto, sem o nome do módulo.
iniciativa = rolar_dado()
print("Iniciativa: " + str(iniciativa))

# Agora use as outras duas funções do módulo:
# esta_vivo() e montar_ficha().
Ver dica

Os dois arquivos precisam estar na mesma pasta, e o import usa o nome do arquivo sem o .py. Se o Thonny reclamar que não encontrou o módulo, quase sempre é porque um dos arquivos foi salvo em outra pasta.

Desafio da semana — Refatorando um desafio antigo

Escreva e teste este desafio no Thonny. Você vai mexer em um programa inteiro, e o "Vá além" sugere separar as funções em um arquivo próprio — o que só funciona lá.

O que você vai construir

Nada novo — e essa é a graça. Você vai pegar um desafio que já entregou (o caixa eletrônico da Aula 6 ou a agenda de contatos da Aula 3) e reorganizar o mesmo programa usando funções, sem mudar o que ele faz por fora.

Por que isso é interessante

Isso tem nome no mundo real: refatorar. É o que acontece em qualquer equipe quando um código funciona mas ficou difícil de mexer. O programa continua igual para quem usa; o que muda é como ele está organizado por dentro. É também o motivo de a Aula 14 existir: lá vocês vão fazer exatamente isso com o jogo.

Requisitos mínimos

  1. Escolher um desafio seu já entregue.
  2. Separar o programa em pelo menos três funções, com nomes descritivos em português.
  3. Pelo menos uma função precisa usar return, não só imprimir.
  4. Cada função tem uma docstring de uma linha dizendo o que ela faz.
  5. O programa principal fica curto e legível no fim do arquivo, basicamente chamando as funções em ordem.
  6. O programa continua funcionando exatamente como antes — mesma experiência para quem usa.

Exemplo de execução

Aqui o exemplo não é o programa rodando (ele roda igual ao de antes!), e sim o que muda no código. Veja um pedaço do caixa eletrônico da Aula 6, antes e depois.

Antes — tudo solto no meio do programa:

escolha = input("Escolha uma opção: ")

if escolha == "3":
    valor = int(input("Quanto você quer sacar? "))
    if valor > saldo:
        print("Saque não realizado: você pediu " + str(valor) + " reais, mas seu saldo é de " + str(saldo) + " reais.")
    else:
        saldo = saldo - valor
        print("Saque de " + str(valor) + " reais realizado. Seu saldo é de " + str(saldo) + " reais.")

Depois — a mesma coisa, virada função:

def sacar(saldo, valor):
    """Devolve o novo saldo depois do saque, ou o saldo original se não houver dinheiro."""
    if valor > saldo:
        narrar("Saque não realizado: você pediu " + str(valor) + " reais, mas seu saldo é de " + str(saldo) + " reais.")
        return saldo

    novo_saldo = saldo - valor
    narrar("Saque de " + str(valor) + " reais realizado. Seu saldo é de " + str(novo_saldo) + " reais.")
    return novo_saldo


# No programa principal, a opção de saque cabe em duas linhas:
valor = int(input("Quanto você quer sacar? "))
saldo = sacar(saldo, valor)

Vá além (opcional)

  • Separar as funções em um arquivo próprio (ferramentas.py) e importar no principal.
  • Criar uma função narrar() única, por onde passam todas as mensagens ao usuário.
  • Acrescentar valores padrão em pelo menos uma função.
  • Escrever as docstrings de forma que outra pessoa consiga usar suas funções só lendo elas.
  • Comparar o tamanho do seu programa principal antes e depois.

Checklist de conclusão

  • O programa faz exatamente o que fazia antes.
  • Tem pelo menos três funções com nomes descritivos.
  • Pelo menos uma usa return.
  • Todas têm docstring.
  • O programa principal cabe em poucas linhas.
  • As mensagens continuam fazendo sentido ouvidas em voz alta.
  • Está publicado no GitHub, ao lado da versão antiga.

Nota de acessibilidade

Esta aula tem uma boa prática que ajuda muito quem usa leitor de tela — e é a mesma coisa que torna seu código melhor para todo mundo: separe a função que calcula da função que fala.

Uma função que só faz a conta e devolve o resultado com return pode ser reaproveitada em qualquer lugar. A função que monta a frase para o jogador fica separada, e é nela que você cuida para a mensagem fazer sentido ouvida em voz alta.

No jogo das próximas aulas, isso vira uma função narrar() única — o lugar certo para melhorar todas as falas do jogo de uma vez só.
